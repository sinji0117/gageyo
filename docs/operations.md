# 운영 안내

운영자가 매일·가끔 하는 일과, 화면으로 안 되는 일을 DB 에서 처리하는 방법입니다.
DB 를 직접 고치기 전에는 **백업을 먼저** 받으세요.

## 매일

운영자 화면 **대시보드**에서 숫자가 있는 카드를 누르면 바로 해당 목록으로 갑니다.

| 할 일 | 화면 |
| --- | --- |
| 입점 심사 (사업자 조회 링크로 확인 → 승인 / 반려 사유) | 업체 관리 → 승인 대기 |
| 정보 변경 요청 승인·반려 | 정보 변경 요청 |
| 무통장 **입금 확인** (입금자명·금액 대조) | 주문 → 입금 대기 |
| 문의·신고 답변 | 문의·신고 |
| 결제 후 취소 요청 처리 | 주문 상세 → 주문 취소 |

## 매달 정산

1. 다음 달 초에 **정산** 화면에서 지난달을 고릅니다.
2. **CSV 내려받기** → 은행 대량 이체로 업체별 지급액을 보냅니다 (사업자번호·지급액 열 포함).
3. 보낸 업체마다 **지급 완료**(메모: 이체 일자 등). 파트너 정산 화면에 지급일이 보입니다.
4. **금액 변동** 표시가 있으면 지급 뒤 환불이 생긴 것입니다. 차액을 업체와 확인해 다음 송금에서 직접 조정하세요.

자세한 계산: [결제 · 환불 · 정산](payments-toss.md#정산)

## 결제 결과를 모를 때

고객이 "카드 승인 문자는 왔는데 주문이 결제 대기"라고 하면 운영자 화면 주문 상세에서 **카드 결제 확인**을 누릅니다.
API 가 토스에서 주문번호로 결제를 찾아, 승인돼 있고 금액이 맞으면 결제 완료로 바꿉니다 (업체 알림 메일, 작업 기록 `order.toss_synced`).

- 결제 대기인 카드 주문을 **취소**할 때(고객·운영자)와 2시간 뒤 **자동 취소**할 때도 먼저 같은 확인을 합니다.
  그래서 토스에서 돈이 빠져나간 주문이 '결제 전 취소'로 끝나는 일은 없습니다. 토스와 통신이 안 되면 취소를 막고 다음에 다시 시도합니다.
- 토스에 승인된 금액이 주문 금액과 다르면(있어서는 안 되는 일) 결제 완료로 바꾸지 않고 오류를 보여 줍니다.
  토스 상점관리자에서 그 결제를 취소하세요. API 로그에 `toss lookup amount mismatch` 가 남습니다.

## 회원·업체

- **정지**: 회원 관리 → 정지(사유). 즉시 모든 기기에서 로그아웃됩니다. 운영자 계정은 정지할 수 없습니다.
- **업체 이용 중지**: 업체 관리 → 이용 중지(사유). 고객 화면에서 사라지고 파트너 센터 견적·예약·주문 메뉴가 막힙니다.
- **예전 파트너 키 업체 옮기기**: 업체 상세 → 비밀번호 설정 링크 → 업체가 링크로 비밀번호를 정하면 이메일로 로그인합니다. 이후 파트너 키는 재발급하지 않아도 됩니다.
- **로그인 잠금 풀기**(5번 실패 → 15분): 기다리거나 DB 에서

  ```sql
  DELETE FROM rate_limits WHERE bucket = 'login-fail:customer:user@example.com';  -- partner · admin
  ```

## 운영자 OTP 를 잃어버렸을 때

OTP 는 본인만 끌 수 있으므로 DB 에서 비웁니다.

```sql
UPDATE users SET totp_secret = NULL, totp_last_step = NULL WHERE email = 'admin@example.com';
DELETE FROM auth_sessions WHERE user_id = (SELECT id FROM users WHERE email = 'admin@example.com');
```

다시 로그인한 뒤 **내 보안**에서 새로 등록하세요. 작업 기록에는 남지 않으니 따로 기록해 두세요.

## 운영자 추가·제거

`ADMIN_EMAILS` 에 이메일을 넣거나 빼고 API 를 다시 시작합니다. 빼면 그 계정은 다음 요청부터 운영자 API 를 못 씁니다.
새 운영자는 운영자 화면에서 **비밀번호 설정 메일 받기**로 시작합니다.

## 백업

| 무엇 | 어디 | 방법 |
| --- | --- | --- |
| DB | MariaDB `gageyo_db` | Rpanel DB 백업 (매일), 또는 `mysqldump --single-transaction gageyo_db` |
| 업로드 이미지 | `UPLOAD_DIR` (Rpanel 은 앱 `data/uploads`) | Rpanel 앱 백업, 또는 폴더 복사 |
| 비밀값 | `DATA_KEY` | 환경 변수를 따로 안전한 곳에 적어 둠. **잃어버리면 운영자 OTP 를 모두 다시 등록**해야 함 |

복원 연습을 한 번은 해 보세요: 빈 DB 에 덤프를 넣고 API 를 켜면 남은 마이그레이션만 적용됩니다.

## 비밀값 바꾸기

| 값 | 바꾸면 |
| --- | --- |
| `DATA_KEY` | 저장된 OTP 비밀값을 읽지 못함 → OTP 를 켠 운영자는 위 'OTP 를 잃어버렸을 때' 처리 후 다시 등록 |
| `ADMIN_API_KEY` | 예전 키로 접속 불가. 비우면 키 접속을 끔 |
| `TOSS_SECRET_KEY` | 이미 결제된 주문의 환불도 새 키로 요청 (같은 상점이어야 함) |
| DB 비밀번호 | `DATABASE_URL` 을 함께 바꾸고 재시작 |

## 오래된 데이터

API 가 한 시간마다 지난 세션·가입 코드·비밀번호 링크·요청 횟수 기록을 지우고, 결제하지 않은 주문을 자동 취소합니다.
주문·예약·작업 기록은 지우지 않습니다 (전자상거래법상 계약·결제 기록 5년 보관). 탈퇴 회원은 개인정보만 지워지고 거래 기록은 남습니다.

## 로그

API 는 표준 출력에 로그를 씁니다 (Rpanel 앱 **로그** 탭). `RUST_LOG=info,gageyo=debug` 처럼 바꿀 수 있습니다.
찾을 만한 문구: `toss confirm transport error` · `toss lookup failed` · `toss amount mismatch` · `메일 보내기 실패` · `unpaid orders expired` · `설정 오류`.
