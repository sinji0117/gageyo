# bandiuri 와 비교

가게요는 [bandiuri](https://github.com/sinji0117/bandiuri)(상점 만들기 플랫폼)의 Rust 모듈형 API · React 워크스페이스 구조를 바탕으로 합니다.
이 문서는 bandiuri 에 있던 기능 중 무엇을 가게요로 옮겼고, 무엇을 일부러 뺐는지, 그리고 이번에 고친 가게요의 문제를 정리합니다.

## 이번에 고친 가게요의 문제

- **빌드가 되지 않음**: 고객 로그아웃 처리 함수의 반환형 오류로 API 가 컴파일되지 않았습니다.
- **목록 API 실패**: MariaDB `ENUM` 열을 sqlx 가 `String` 으로 읽지 못해 업체·견적·예약 목록이 오류. → `VARCHAR` 로 바꾸고 앱에서 검사.
- **좌표 읽기 실패**: `DECIMAL` 좌표를 `f64` 로 못 읽음 → `DOUBLE`. 반경 검색·거리순은 서버에서 계산.
- **시간대**: DB 연결 시간대를 한국 시간으로 맞춤 (영업시간·예약 검사 기준).
- **파트너·소개 화면 개발 서버**에 `/api` 프록시가 없어 API 를 부르지 못함.
- **파트너 키만으로 접속** → 계정(이메일·비밀번호) 로그인과 입점 신청 추가. 예전 키는 계속 받음.
- **운영자 키만으로 접속** → 운영자 계정·OTP·작업 기록.
- 파트너 주문 화면에 **다른 업체 상품까지 합친 금액**이 보임 → 우리 업체 줄만.
- 운영자가 판매 중지한 상품이 **파트너 수정만으로 다시 판매 중**이 됨 → 파트너는 못 엶.
- 견적 보내기가 브라우저 입력창 두 개 → 금액·내용·유효 기간 창. 견적 선택 전 고객 연락처 가림.
- 예약이 영업시간·휴무일·지난 시간을 확인하지 않음 → 서버 검사.
- 주문 금액을 화면 값으로 믿음 → 서버가 상품 가격으로 다시 계산, 재고 차감·복원.
- **결제 없이 '주문 완료'** → 카드·무통장 결제와 결제 대기, 결제하지 않은 주문 자동 취소.
- 실제 업체가 아닌 사진을 업체 사진처럼 보여 줌 → 사진이 없거나 열리지 않으면 이름 그림.
- 첫 화면 숫자(업체 수·평점)가 고정값 → `/api/stats` 실제 값.
- 운영자 대시보드 '새로고침'이 숫자를 다시 받지 않음, 회원·신고 메뉴는 '준비 중' → 구현.
- 문서가 Redis·MongoDB·`ADMIN_API_KEY` 만 설명 → 지금 구조에 맞게 다시 씀.
