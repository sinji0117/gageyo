# 결제 · 환불 · 정산

가게요는 **플랫폼이 결제를 받고, 매달 업체에 수수료를 뺀 금액을 보내는** 방식입니다 (오픈마켓형).
결제 수단은 운영자가 켠 것만 고객 주문서에 보입니다.

| 결제 수단 | 켜는 방법 | 결제 완료 시점 |
| --- | --- | --- |
| 카드·간편결제 (토스페이먼츠 결제창) | `TOSS_CLIENT_KEY` + `TOSS_SECRET_KEY` | 결제창에서 돌아와 서버가 승인했을 때 |
| 무통장입금 | 운영자 화면 **결제·운영 설정**의 은행·계좌번호·예금주 (세 칸 모두) | 운영자가 **입금 확인**을 눌렀을 때 |
| 업체와 직접 결제 (주문만 접수) | 위 두 가지가 **모두 꺼져 있을 때만** | 운영자가 **결제 완료로**를 눌렀을 때. 정산 대상 아님 |

## 카드 결제 흐름

```text
고객 주문서 ── POST /api/orders ──▶ 주문 payment_pending, 재고 차감
   │  응답의 toss{client_key, order_id, amount, order_name}
   ▼
토스 결제창 (브라우저, js.tosspayments.com/v2/standard)
   │  성공: app.gageyo.com/?pay=success&paymentKey=…&orderId=…&amount=…
   │  실패: ?pay=fail&code=…&message=…   → 주문서에서 '결제 다시 하기'
   ▼
POST /api/orders/{id}/payments/toss {payment_key, amount, phone?}
   1. 주문이 카드 결제 · payment_pending 인지
   2. amount == 서버의 주문 금액인지 (다르면 거부 — 주소 조작 방지)
   3. 토스 승인 API → 승인 금액 다시 대조
   4. 주문 paid, 줄마다 수수료 고정, 고객·업체 메일
```

- 같은 결제를 두 번 확인하면(새로고침) 같은 결과를 돌려줍니다. 다른 결제 키로 이미 처리된 주문은 409.
- 카드사 거절은 **402**와 토스의 안내 문구로 돌아옵니다. 토스와 통신이 끊기면 503 과 "카드사 승인 문자가 왔다면 고객센터로" 안내를 보여 주고,
  서버 로그에 `toss confirm transport error` 를 남깁니다. 운영자는 주문 상세의 **카드 결제 확인**으로 토스에서 결제를 찾아 맞출 수 있습니다
  → [운영 안내](operations.md#결제-결과를-모를-때).
- 결제 대기인 카드 주문을 취소·자동 취소하기 전에는 항상 토스에서 주문번호로 결제를 찾아 봅니다 (`GET /v1/payments/orders/{orderId}`).
  승인돼 있으면 취소 대신 결제 완료로 맞추고, 운영자 취소라면 이어서 환불합니다.
- 토스 키는 서버에만 있고(`TOSS_SECRET_KEY`), 화면은 `/api/orders` 응답과 `/api/checkout/config` 로 클라이언트 키만 받습니다.
- `test_` 키와 `live_` 키를 섞으면 서버가 켜지지 않습니다.

## 결제하지 않은 주문 자동 취소

주문하는 순간 재고를 잡아 두므로, 결제하지 않고 떠난 주문은 API 가 한 시간마다 자동 취소하고 재고를 돌려놓습니다.

| 결제 수단 | 자동 취소 |
| --- | --- |
| 카드 | 주문 뒤 **2시간** 동안 승인이 없으면 (토스에 승인된 결제가 있으면 취소하지 않고 결제 완료로) |
| 무통장 | **입금 기한**(운영 설정, 기본 48시간) **+ 24시간** 동안 입금 확인이 없으면 |
| 업체와 직접 결제 | 자동 취소하지 않음 |

고객에게 취소 메일이 가고(사유 "결제가 완료되지 않아 자동 취소" · "입금 기한이 지나 자동 취소"), 방문 장착 예약도 함께 취소됩니다.

## 취소와 환불

| 누가 | 언제 | 결과 |
| --- | --- | --- |
| 고객 | 결제 전 (`payment_pending`) | 취소, 재고 복원 |
| 고객 | 결제 후 | 화면에서 직접 못 함 → 고객센터 문의 → 운영자 |
| 운영자 | 발송된 상품이 없는 주문 | 카드: **토스 전액 자동 환불** (`refunded`) · 무통장: `refunded` 로 바꾸고 화면에 "직접 송금" 안내 · 결제 전: `cancelled` |
| 운영자 | 발송된 상품이 있는 주문 | 막힘. 반품을 받은 뒤 토스 상점관리자에서 부분 취소하고 정산에서 조정 |

- 환불 요청은 `Idempotency-Key = gy-cancel-{주문번호}` 로 보내 두 번 눌러도 한 번만 환불됩니다.
- 토스가 환불을 거절하면 주문 상태는 그대로이고 거절 사유가 화면에 보입니다.
- **부분 취소**(일부 상품만)는 아직 화면이 없습니다. 토스 상점관리자에서 처리하세요.

## 정산

매출 = 플랫폼이 받은 결제(카드·무통장)의 **결제 완료 시각 기준 월** 합계 (취소·환불된 주문과 취소된 줄 제외).

```text
업체 지급액 = 그 달 우리 업체 상품 줄 금액 합계 − 수수료 합계
수수료      = 결제 완료 때 줄마다 FLOOR(금액 × 수수료율) 로 고정
```

- **수수료율**은 운영자 화면 결제·운영 설정에서 0~30% (0.01% 단위)로 정합니다. 바꿔도 **이미 결제된 주문의 수수료는 그대로**입니다.
- 운영자: 정산 화면에서 월을 고르면 업체별 매출·수수료·지급액·주문 수와 합계가 보입니다. **CSV 내려받기**(엑셀용 BOM 포함)로 은행 대량 이체 파일을 만들 수 있습니다.
  송금한 뒤 **지급 완료**를 누르면 그때 금액·메모·처리자가 기록됩니다. 끝난 달만 기록할 수 있고, 잘못 눌렀으면 기록을 지울 수 있습니다.
- 지급 뒤 환불이 생겨 금액이 바뀌면 운영자·파트너 화면에 **금액 변동**이 표시됩니다. 차액은 운영자와 업체가 확인해 처리합니다 (자동 상계 없음).
- 파트너: 정산 메뉴에서 연도별 월 매출·수수료·지급액·지급 여부를 봅니다.
- 실제 송금(펌뱅킹)과 세금계산서 발행은 시스템 밖에서 운영자가 합니다.

## 운영 전에

1. 토스페이먼츠 가맹 계약 → 상점관리자에서 **테스트 키**를 받아 넣고 실제 결제창으로 승인·실패·환불을 해 봅니다.
2. 계약 심사가 끝나면 `live_` 키로 바꾸고 API 를 다시 시작합니다. 적은 금액으로 실제 결제 → 운영자 취소(환불)까지 확인합니다.
3. 토스 상점관리자의 정산 주기·수수료와 가게요 수수료율을 맞춥니다 (가게요 수수료는 PG 수수료와 별개).
